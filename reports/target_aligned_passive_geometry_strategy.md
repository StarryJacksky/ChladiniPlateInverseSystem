# TAGS 目标对齐被动几何策略说明

本文档记录一个重要的算法边界修正：项目主线不应变成“增加外部实验设施”，而应保持为“设计一块可打印的被动 Chladni 板”。因此，多激励器、外部贴块、可调支撑、外部弹簧阻尼等方案不应作为主线。真正应该升级的是板件本身的隐藏几何参数化。

---

## 1. 这次修正解决了什么问题

之前 MOSAIC-Z 的激进版本把变量扩展到了：

- 第二激振器。
- 多点相位控制。
- 外部可调支撑。
- 外部质量块。
- 外部弹簧或阻尼。

这些方向虽然能增加物理自由度，但会改变项目性质。项目会从：

> 设计一块板。

变成：

> 设计一整套主动实验系统。

这会带来几个问题：

1. 实验装置复杂。
2. 用户部署困难。
3. COMSOL 与真实实验更难一致。
4. 报告逻辑容易被质疑，因为图案可能来自外部设施，而不是板的逆向设计。
5. 客户最终拿到的不是一块可打印板，而是一套需要调试的系统。

所以更合理的主线应该是：

> 不增加外部实验设施，只优化被打印的单块板本身。

同时还有一个配套原则：

> 不再把 Python 简化物理预测当作主线反馈。Python 负责生成目标对齐几何、调度 COMSOL 和评分 COMSOL 输出；真实模态和频域响应必须由 COMSOL 给出。

---

## 2. 项目边界：什么不做，什么可以做

### 不建议作为主线的变量

这些属于额外实验设施，不适合作为当前项目主线：

| 变量 | 为什么不适合 |
|---|---|
| 第二激振器 | 增加硬件、相位控制和部署难度 |
| 外部可调支撑 | 让实验结果依赖手动调参 |
| 外部贴质量块 | 破坏“一体化打印板”的项目边界 |
| 外接弹簧/阻尼器 | 让系统变成复杂机电装置 |
| 多个外部附件 | 可复现性和用户部署都会变差 |

### 可以作为主线的变量

这些属于被动打印几何，是板本身的一部分：

| 变量 | 为什么可以 |
|---|---|
| 局部厚度变化 | 原项目已有变量，属于板自身结构 |
| 下表面浅槽 | 不影响上表面撒沙，但能改变刚度 |
| 下表面加强肋 | 一体化打印，不是外接设施 |
| 下表面局部凸起 | 等效改变质量和刚度 |
| 轻微边界形状扰动 | 仍是一块板的几何设计 |
| 标准化中心固定区 | 保持实验装置一致 |

核心原则是：

> 上表面保持平整，沙粒只受振动影响；所有结构调制尽量隐藏在下表面或板内部。

---

## 3. TAGS 的核心思想

TAGS 可以理解为：

> Target-Aligned Geometry Subspace，目标对齐几何子空间。

它不是继续在普通方格厚度场里随机搜索，而是让目标图案从一开始就参与定义板的几何基函数。

旧方法是：

```text
普通网格厚度场 -> COMSOL -> 看哪个结果碰巧像目标
```

TAGS 是：

```text
目标图案骨架 -> 目标对齐几何区域 -> 被动下表面厚度调制 -> COMSOL -> 验证低振幅线是否贴合目标
```

这条路线的关键变化是：

> 目标不再只进入评分函数，而是进入结构参数化方式。

---

## 4. 为什么这不是作弊

不推荐的做法是：

> 在上表面直接刻出 IC 槽，让沙粒被几何卡住。

这不是真正的 Chladni 图案，因为沙粒会被槽挡住。

TAGS 推荐的是：

> 上表面保持平整，下表面根据目标图案做隐藏厚度、浅槽或加强肋，沙粒仍然只根据振动低幅区域聚集。

这仍然是动力学逆向设计。目标图案不是被画在表面，而是通过改变刚度矩阵和质量矩阵影响振动响应：

```text
hidden geometry -> K, M change -> vibration response changes -> sand accumulates at low-amplitude regions
```

---

## 5. 为什么普通方格厚度场容易失败

普通方格厚度场的问题不是网格数量本身，而是参数空间和目标图案没有几何关系。

它有几个缺陷：

1. 方格边界通常不沿着 logo 轮廓。
2. 弯曲字母需要很多格子才能粗略表达。
3. 优化器大量时间浪费在和目标无关的区域。
4. 目标只在最后评分时出现，没有指导结构空间。
5. 方板自然模态容易回到中心环、星形、放射线等低复杂度形状。

所以问题不只是“网格太粗”，而是：

> 参数化方式没有把目标几何嵌入物理变量。

---

## 6. TAGS 的几何参数化方式

假设目标图案经过预处理后得到骨架线 `T`。围绕目标线定义几个区域。

### 目标骨架带

```text
B0 = dist(x, T) < r0
```

这是最接近目标线的区域。

### 目标侧带

```text
B1 = r0 <= dist(x, T) < r1
```

这是目标两侧的保护带，用于制造振幅对比。

### 背景区域

```text
B2 = outside B0 and B1
```

这是普通背景。

厚度场可以写成：

```text
h(x, y) = h_base + a0 * B0 + a1 * B1 + a2 * B2
```

更进一步，可以把目标骨架拆成多个片段：

```text
T = T1 + T2 + ... + TN
```

每个片段有自己的局部调制：

```text
h(x, y) = h_base + sum_i ai * Bi(x, y)
```

这样参数不再是任意网格，而是围绕目标组织的低维几何基函数。

---

## 7. 对当前项目最实用的最小实验

不要一开始就做复杂优化。应该先做三个能快速判断方向的被动几何 case。

### Case A：目标带加厚

```text
目标骨架附近更厚
背景保持默认厚度
```

目的：判断目标线附近加刚度是否能形成低振幅线或改变模态。

### Case B：目标带变薄

```text
目标骨架附近更薄
背景保持默认厚度
```

目的：判断目标线附近柔化是否更容易形成目标低振幅区域。

### Case C：目标带薄，侧带厚

```text
目标骨架附近变薄
目标两侧保护带加厚
背景保持默认厚度
```

目的：制造目标线和两侧的振幅对比，是最值得优先测试的版本。

这三个 case 的意义不是马上得到最终 IC，而是判断：

> 目标对齐被动厚度参数化是否比普通网格厚度更有方向性。

## 8. 仿真类型建议

TAGS 可以用于 eigenfrequency，也可以用于 frequency-domain。

但从真实实验角度看，更建议 frequency-domain，因为实际 Chladni 实验通常是中心激振并扫频：

```text
[K - omega^2 M + i omega C] u = f
```

这并不增加外部实验设施。它只是让仿真更接近真实实验。

推荐顺序：

1. 仍保留 eigenfrequency，用于看模态家族是否被几何改变。
2. 增加或优先使用 frequency-domain，用于评估真实扫频下的低振幅区域。
3. 评分时看上表面 `|u_z|` 的目标线低振幅，而不是只看某个 eigenmode 的零线。

---

## 9. TAGS 应该使用的评分目标

TAGS 不应该只优化 IoU。更合理的是 valley score：

### 目标线上低振幅

```text
L_target = mean(A(x)^2 for x on target)
```

其中 `A(x) = |u_z(x, omega)|`。

### 目标两侧要有对比

```text
L_contrast = max(0, mean(A_target) - mean(A_side) + margin)
```

意思是目标线要比旁边更安静，否则沙粒线条不清楚。

### 远离目标不要到处低振幅

惩罚背景区域出现大量低振幅线，避免生成一堆和目标无关的节点。

### 制造约束

惩罚过薄、过厚、过陡、不可打印或应力集中的几何。

最终目标大致是：

```text
L = target_low_amplitude
  + side_contrast
  + extra_valley_penalty
  + smoothness
  + manufacturability
```

## 10. 这对 MOSAIC-Z 的修正

MOSAIC-Z 的核心思想仍有价值：

> 不要只优化一个 mode，要优化可激发的响应空间。

但变量边界应该收缩：

| 原激进方向 | 修正后的主线 |
|---|---|
| 多激振器 | 保持原中心激振 |
| 外部支撑点 | 保持标准中心固定区 |
| 外部质量块 | 改成一体化下表面厚度/凸起 |
| 外部可调附件 | 改成一次性打印被动几何 |
| 任意 topology | 改成目标对齐、可制造的下表面几何 |

因此，新的主线不是放弃 MOSAIC-Z，而是把它变成：

```text
target-aligned passive geometry
-> COMSOL modes / frequency response
-> modal-subspace feasibility
-> valley score
-> printable passive plate
```

---

## 11. 对现有代码和规划的影响

当前最值得调整的不是继续堆更多候选，而是确认三件事：

1. 目标图案能否生成目标对齐几何基函数。
2. 这些基函数能否被物化成真实 COMSOL 几何或足够可靠的等效厚度场。
3. Frequency-domain 评分能否判断目标线低振幅，而不是只评价单个 eigenmode。

这里的 frequency-domain 评分应当基于 COMSOL 输出，而不是 Python 自己预测的强迫响应。Python 可以生成候选和计算分数，但不能替代 COMSOL 给出响应场。

如果只把 TAGS 做成粗糙的 15×15 栅格，它可能仍然太弱。更理想的是：

- Python 生成连续下表面高度场。
- COMSOL 使用插值函数或 CAD 几何构建真实厚度分布。
- 最终导出可打印 STL 或 CAD。

短期可以先用等效厚度场验证方向，但长期应该走真实几何。

---

## 12. 当前算法报告需要更新的判断

原先报告里提到的第二激振器、多激励相位、外部支撑等，不应作为项目主线。它们最多是学术备选或远期实验，不适合当前客户部署目标。

更准确的当前判断是：

> 当前算法的主要问题不是缺少外部控制自由度，而是目标图案没有足够早地进入被动板件几何参数化。普通网格厚度、密度和损耗场太间接，导致优化器在大量与目标无关的结构空间中搜索。

所以近期最应该做的突破是：

> 从普通网格厚度搜索，升级到目标对齐的被动下表面几何搜索。

---

## 13. 最终结论

TAGS 的价值在于，它保留了项目的干净边界：

```text
一块打印板 + 原有中心激振/固定方式 + 扫频 + 沙粒
```

同时又让算法跳出旧方格厚度搜索：

```text
目标图案 -> 目标对齐下表面几何 -> 被动刚度/质量调制 -> 低振幅图案
```

一句话总结：

> 不要增加实验设施；让目标图案进入板的被动几何参数化，而不是只进入 Python 的评分函数。

## 14. 当前已实现的最小 TAGS 生成路径

当前已经加入一个最小可验证实现：

```text
src/tags/target_aligned_geometry.py
scripts/generate_tags_candidates.py
```

它不做 Python 物理预测，只做几何生成：

```text
processed target_binary.npy
-> skeleton
-> target band / side band
-> A/B/C 三类被动厚度矩阵
-> H.csv / density_scale.csv / loss_factor.csv
-> comsol_parameters.csv
```

生成命令：

```bash
python scripts/generate_tags_candidates.py --prefix tags_ic
```

本次生成的三个正式候选是：

```text
candidates/tags_ic_case_a_target_thick
candidates/tags_ic_case_b_target_thin
candidates/tags_ic_case_c_target_thin_side_thick
```

三类候选含义：

| 候选 | 含义 |
|---|---|
| `case_a_target_thick` | 目标骨架带加厚，背景中等厚度 |
| `case_b_target_thin` | 目标骨架带变薄，背景中等厚度 |
| `case_c_target_thin_side_thick` | 目标骨架带变薄，两侧保护带加厚 |

为了隔离“厚度矩阵生成算法本身”的效果，这三个候选的辅助物理场保持中性：

```text
density_scale.csv = 1
loss_factor.csv = 0
```

下一步应该让 COMSOL 对这三个候选做真实 eigenfrequency 或 frequency-domain 仿真，再用 Python 评分 COMSOL 输出。不要用 Python 预测响应来判断它们是否成功。

## 15. 第一轮 COMSOL-first 真实结果

已经对三个 TAGS 候选运行真实 COMSOL eigenfrequency，导出 40 个模态，并用现有单模态评分函数评价。

| 候选 | 最佳模态 | 频率 Hz | IoU | Dice | final_score |
|---|---:|---:|---:|---:|---:|
| `tags_ic_case_a_target_thick` | 14 | 425.944 | 0.00565 | 0.01124 | -0.00584 |
| `tags_ic_case_b_target_thin` | 8 | 165.022 | 0.01595 | 0.03140 | 0.00140 |
| `tags_ic_case_c_target_thin_side_thick` | 8 | 190.011 | 0.01671 | 0.03287 | -0.00497 |

这个结果说明：

1. TAGS 的代码路径已经真正进入 COMSOL，不是 Python 预测。
2. 单纯把目标骨架映射到 15×15 厚度场，第一轮没有直接产生接近 IC 的单个 eigenmode。
3. Case B/C 比 Case A 略好，说明“目标带变薄”可能比“目标带加厚”更有希望，但差距还很小。
4. 这个结果支持新的判断：问题不只是后处理，也不只是频率，而是当前 15×15 目标对齐厚度场仍然太粗、太弱。

下一步不能退回 Python forced-response prediction。更合理的是：

```text
1. 继续基于 COMSOL 做 frequency-domain 真实验证；
2. 把 TAGS 从 15×15 方格场升级成连续下表面高度场或真实下表面浅槽/肋；
3. 保持上表面平整，不增加外部设施；
4. 用 COMSOL 输出评分，更新下一批 TAGS 参数。
```

## 16. 补充：不能只看单模态，必须看 COMSOL 模态子空间

第一轮单模态评分只是旧评分基线。它会低估 TAGS，因为真实结构导出的多个 COMSOL eigenmodes 可以形成线性组合。为了纠正这一点，已经对三个 TAGS 候选运行 MOSAIC-Z subspace feasibility：

```text
COMSOL mode_08 到 mode_40
-> Python 只做线性代数组合优化
-> 不把它当真实强迫响应
-> 用它判断 COMSOL 模态基底是否有目标表达能力
```

结果如下：

| 候选 | modes | Subspace IoU | Subspace Dice | Layout | Loss |
|---|---|---:|---:|---:|---:|
| `tags_ic_case_a_target_thick` | 8-40 | 0.10499 | 0.19003 | 0.54409 | 0.58244 |
| `tags_ic_case_b_target_thin` | 8-40 | 0.09960 | 0.18116 | 0.51383 | 0.60398 |
| `tags_ic_case_c_target_thin_side_thick` | 8-40 | 0.09151 | 0.16767 | 0.50115 | 0.60384 |

这说明：

1. 用户提醒是对的，单模态不是正确的主要判断方式。
2. TAGS 的模态子空间表现明显高于单模态结果，尤其 A 案例的 Dice 从 0.011 提到 0.190。
3. 但即便看线性组合，当前 TAGS 仍没有达到之前较强候选的水平。
4. 线性组合只是“表达能力诊断”，不是“实验可激发证明”。下一步仍需要 COMSOL frequency-domain 验证，而不是 Python forced-response prediction。

当前 A 案例的最佳组合主要依赖：

```text
mode 10 @ 287.244 Hz
mode 17 @ 500.180 Hz
mode 32 @ 1230.064 Hz
mode 22 @ 688.359 Hz
mode 19 @ 572.174 Hz
```

这提示：如果只用单一中心激振频率，可能很难同时激起这个自由组合。后续要么通过 COMSOL frequency-domain 检查自然可激发程度，要么继续改被动几何，使目标图案更接近少数强模态或窄频段响应。
