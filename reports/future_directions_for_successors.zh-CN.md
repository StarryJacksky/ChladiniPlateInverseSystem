# 未来改进方向（交接给后辈）

> 对 `paper/improvement_directions_zh.tex`《五个算法改进方向》的**勘误与重定向**。
> 本文基于 2026-06 的一轮决策实验，在项目结案后写就，目的是让接手者不要在错误的方向上重复投入。
> 语言 / Language：[中文](./future_directions_for_successors.zh-CN.md) ｜ [English](./future_directions_for_successors.en.md)

## 0. 为什么有这份文档

原《五个算法改进方向》报告把改进重心放在**优化器/评分**侧（评分重构、几何损失、频率内循环、随机重启、中心伪影修正）。结案前的一轮决策实验表明：**这五个方向都不能解决项目真正的瓶颈**——即"COMSOL 里显示的图案在真实板上震不出来"。本文给出经过验证的诊断，并按优先级重排真正值得做的方向。

## 1. 一句话结论

> **项目真正的瓶颈从来不是优化算法，而是：整条链路始终在"仿真内部"自证（surrogate → COMSOL，且把 COMSOL 当真理却从未拿真实板标定过），并且被优化器逼到了物理上不可复现的离共振工作点上。**
> 因此"COMSOL 有图、现实没有"不是某个 bug，而是这套方法论的必然结果。`4.85× 富集`是一个**仿真内部的数字**，从未锚定到现实。

## 2. 可信度分级（请后辈务必先读）

本文每条结论都标注来源等级，**不要把估计当定论**：

| 标记 | 含义 | 可信度 |
|---|---|---|
| 【COMSOL真值】 | 来自 COMSOL 本征频率/强迫响应导出 | 高 |
| 【代码核实】 | 直接阅读源码确认 | 高 |
| 【surrogate估计】 | 用 25×25 粗网格替代模型算出，**需 COMSOL/实测复核** | 中 |
| 【待实测】 | 必须用真实板实验才能确认 | 未验证 |

复现脚本见 §6。

## 3. 核心诊断

### 3.1 "木星"（中心团块/圆环）是中心夹持的恒在伪影，不是你该担心的事
【代码核实】中心 8mm 被夹持（`orthotropic_plate.py` 的 `clamp_indices`/`expand_to_grid` 把中心自由度置 0），而撒粉模型 `p = exp(-(|u|/ε)²)`（`amplitude_valley_score.py`，ε=0.08）把"振幅小"判为"积沙"，于是中心被误判为最安静处。**只要画的是相对位移场，木星就在，与是否共振无关**——这也是为什么近期、on-resonance 的交付件 .mph 里照样有木星。
- 原报告对该机理的诊断**正确**。
- 但现实里板中心是被**螺栓/夹具占住**的，本就不会有沙图案，所以木星是个**画面伪影**，对真正可用的外围图案无影响。生产配置 `remove_center_region: true` 已经在评分时排除中心，做法正确（纯化妆）。
- ⚠️ 原报告提出的"正修"——改用绝对位移 `u_abs = u_rel + a_base/ω²`、声称"幻影沙自动消失"——【surrogate估计】**实测无效**：在真实 production_design 前向解上，中心撒粉占比反而从 31% 升到 46%，外围图案被改动 14%。原因是该设计动态放大倍率只有 ~4，基底项不可忽略。**不要在这个"正修"上花时间。**

### 3.2 真正的根因之一：系统性的离共振驱动
【COMSOL真值】对 32 个"设计↔COMSOL本征频率"配对扫描：**23 个设计把 <50% 的驱动能量打在共振点之外**（判据：到最近 COMSOL 本征频率的间距 ≤ 半功率带宽 ζf，ζ=0.02 才算 on-resonance），很多在 0–20%。
- 基础 `production_design` 仅 **4% on-resonance**：主导频率 165.4 Hz（权重 0.604，即报告所说"幸运频率"）偏离最近本征频率 2.87 个带宽；1099 Hz（权重 0.289）偏 25 个带宽；约 **36% 的驱动能量落在 800–1000 Hz 这段"一个本征模都没有"的模态荒漠**。
- 物理后果：离共振 → 强迫响应弱且多模混叠 → 真实模态图案很淡（于是中心伪影相对更显眼）→ 且真实板模态因材料/打印偏移后，同样的离共振频率又是另一团弱响应 → **现实复现不了 COMSOL 的相对位移图**。
- 注：精修迭代 `production_design_p2it5` 达 **96% on-resonance**（材料 sr=1.87），说明后期 Phase-2 是往共振点收的；但权重最大的工作点仍偏离。

### 3.3 为什么优化器会奔向离共振？——撞上物理天花板
【代码核实】【待实测】单点中心激励 + 正方形 D4 对称 → 只有**对称模态（A1 族）被有效激发且可复现**。IC 这类非对称目标，在 on-resonance 的对称模态里根本表达不出来。优化器按"相对位移图像不像目标"打分，于是被**结构性地**推向那些"碰巧像 IC"的离共振工作点——而这些点物理上不可复现。**换句话说，流水线"能做出 IC"恰恰是靠了不可复现的离共振频率。** 这正是"COMSOL↔现实"矛盾的根。原报告的"物理天花板"一节方向正确，但**严重低估了它的中心地位**。

### 3.4 模型自洽性缺陷：surrogate 与 COMSOL 用了不同的激励
【代码核实】surrogate 用**整板基础惯性激励**（`direct_forced_response`: `force = -M·base_accel`），而 COMSOL runner 用**带位置/幅值/相位的高斯点激励**（`run_chladni_forced_response.m`: `build_gaussian_force_expression` + `try_apply_shell_force`）。两者不是同一个物理问题——优化器在 A 物理下选板、却用 B 物理验收。生产设计实际用单个中心激振器（与真实台子一致），但 surrogate↔COMSOL 的这层不一致仍是隐患。

### 3.5 材料错配是孤例，不是系统性问题
【COMSOL真值】32 对里仅 **1 对**材料不一致：过时的基础 `production_design`（优化器 sr=1.0 各向同性 vs COMSOL sr=1.67）。所有电池设计与 production_design 的 p2it1–p2it5 材料都一致。**这一条上轮我曾误判为"第二个系统性根因"，在此更正：它只是个 stale 旧文件。**

## 4. 真正的改进方向（按优先级，原报告完全没排对次序）

### 方向 0（地基，最重要）— 闭合"COMSOL → 真实板"验证回路
全项目**没有任何一步**验证过 COMSOL 能预测真实板。接手第一件事：打印一块板，**实测其本征频率与模态**（敲击法/激光测振，或扫频撒沙拍照），反过来拟合 COMSOL 的材料与边界参数。在此之前 COMSOL 是**未经检验的裁判**，所有下游数字（含 4.85×）都悬空。**没有这一环，其余改进都是空中楼阁。**

### 方向 1 — 把"物理可复现性"当成硬约束
证据见 §3.2。后辈应：**只在隔离良好的本征频率上驱动**（间距 ≫ 带宽，抗标定误差），并在优化目标里**显式惩罚离共振 / 密集模态工作点**。建议引入"可复现性分 = 动态放大倍率 × 模态隔离度"，低于阈值的设计无论多像目标都淘汰。
- 【surrogate估计】对 production_design，推荐的隔离 + on-resonance 候选频率（≤600Hz、间距≥4 带宽）：**58 / 132 / 264 / 371 Hz**；避开 800–1000Hz 模态荒漠。具体数值需用 COMSOL 本征频率复核。

### 方向 2 — 诚实面对物理天花板：要么换目标，要么换物理
证据见 §3.3。二选一：
- (a) 把目标库限制在**物理可达的对称 / 模态可表达**图案；或
- (b) **改物理**——多激振器相控阵 / 分布式或边缘激励 / 非对称边界，真正打破 D4 对称约束。报告里被放弃的 `mosaic_z` 六点相控方案其实是 (b) 的正确雏形，**前提是真实台子能做多点相控驱动**。

### 方向 3 — 修模型自洽性（不是修木星）
证据见 §3.4。先**统一三处激励模型**（surrogate / COMSOL / 真实台子），并验证 surrogate 是否真能预测 COMSOL。木星只需**排除被螺栓占住的中心区**（已在做），不必理会报告的"绝对位移正修"（§3.1，实测无效）。

### 方向 4 — 评分重构（即原报告方向 1–4）排在最后，不是最前
报告主张的"富集度高≠像、改用 F_β / 几何损失 / 频率内循环 / 随机重启"本身**没错**，但**次序错了**：在未校准、离共振的地基上把评分做得更精，只是把一个虚构优化得更精确。等方向 0–3 落地、裁判可信后，再精修评分才有意义。

## 5. 元教训

**本项目最大的方法论缺陷：全程在仿真里闭环，把 COMSOL 当真理，却从未让真理面对现实。**
留给后辈的一句话：**先建实验验证回路，把物理可复现性当硬约束，并诚实承认——单点激励的方形板做不出任意非对称图案。**

## 6. 复现方式

- Python 环境：本机 `python` 不在 PATH；项目用 conda 环境 **`comsol_env`**（`D:\python\anaconda\envs\comsol_env\python.exe`，含 torch 2.12）。从仓库根运行：`$env:PYTHONPATH="."; & <python> scripts\<name>.py`。读 UTF-8 文件务必 `encoding="utf-8"`（Windows 默认 GBK 会报错）。
- 决策实验脚本（只读，`scripts/_decexp_*.py`）：
  - `_decexp_center_artifact.py` / `_decexp_center_probe2.py` — 量化木星伪影（surrogate vs COMSOL 场）。
  - `_decexp_standing_wave_purity.py` — COMSOL 实部/虚部场的驻波纯度（=1.000，干净驻波）。
  - `_decexp_dir5_effectiveness.py` — 方向五"正修"效果（实测无效，31%→46%）。
  - `_decexp_amplification_sweep.py` — 放大倍率扫频（设计扎堆低放大频率）。
  - `_decexp_comsol_resonance_check.py` — 驱动频率 vs COMSOL 本征频率（4% on-res + 材料错配）。
  - `_decexp_step1_material_and_resonance.py` — 32 对材料一致性 + on-resonance 普查 + 推荐频率。
- 输出图与 JSON 在 `reports/_decision_experiments/`。
- 关键数据：`reports/modal_calibration/*_comsol_eigfreqs.json`（COMSOL 本征频率）、各设计的 `frequencies_hz.csv`/`weights.csv`/`w10_optimization_summary.json`、`reports/.../comsol_forced_{real,imag}_grid.npy`（COMSOL 复数场）。

> ⚠️ 注意：§4 方向 1 的推荐频率、§3.1 的"正修无效"、放大倍率等为 **surrogate 估计**，方向 0 的实测标定完成前，应先用 COMSOL 复核、再用真实板验证。
